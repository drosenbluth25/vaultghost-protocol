## Interface findings

### Core data model

`vaultghost-core` defines a signed `TurnRecord` requiring:

- `type` equal to `TurnRecord`;
- `version`;
- `data`;
- an Ed25519 `signature` containing `alg`, `pubkey`, and `sig`.

### Verifier data model

`vaultghost-verify` validates a separate run-manifest test vector containing a run ID, ordered steps, hash-chain relationships, and receipt matching. Its README and passing CI establish that its included manifest is reproducibly verified and that an intentional modification is rejected.

### Ledger data model

`vaultghost-chain-ledger` maintains `CHAIN_INDEX.json`, byte-level artifacts, run-level statuses, SHA-256 values, and an explicitly documented missing upstream artifact. Its passing CI establishes repository-internal file/index correspondence only.

## Material contradictions

1. `vaultghost-protocol` claims canonical authority, but its current normative content does not describe the passing implementation stack.
2. `vaultghost-core` and `vaultghost-verify` currently expose different principal artifact models: signed TurnRecords versus a run-manifest/hash-chain test vector.
3. `vaultghost-chain-ledger` records a separate historical relay-chain artifact set and does not presently demonstrate ingestion from either current component.
4. Therefore, the three passing CI baselines cannot be aggregated into an end-to-end VaultGhost PASS.

## Minimum remediation required

1. Rewrite or replace the operational portion of the canonical specification so it normatively defines the implemented core artifact and verification boundaries.
2. Select one canonical exchange artifact for the first release: either the signed TurnRecord, the run manifest, or a formally defined envelope containing both.
3. Add one cross-repository conformance fixture generated by `vaultghost-core` and consumed by `vaultghost-verify`.
4. Define how a successful verification report is represented and bound into `vaultghost-chain-ledger`.
5. Add a GitHub Actions integration workflow pinning exact default-branch commits or release tags from all participating repositories.
6. Preserve the current research concepts as non-normative experimental material unless separately validated.
